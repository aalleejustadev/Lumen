## Layout

- `app/` — App Router routes. `layout.tsx` wires the Figtree/Geist Mono fonts, the `ThemeProvider`, and the marketing `SiteHeader`; `globals.css` holds all Tailwind/theme tokens.
- `components/ui/` — shadcn/ui primitives. Generated by the CLI; add with `npx shadcn@latest add <name>` rather than hand-writing them, and avoid gratuitous edits since the CLI can overwrite them. Don't run Prettier across this directory — it creates churn in generated files.
- `components/shared/` — pieces used by more than one surface (`logo.tsx`, `theme-toggle.tsx`).
- `components/marketing/` — the marketing site (`site-header.tsx`, `hero-section.tsx`, `stats-section.tsx`, sections, footer). Sections own their own backdrop; page-level files just stack sections.
- `components/<surface>/` — one directory per surface as they land: `dashboard/`, `auth/`.
- `components/theme-provider.tsx` — root-level provider, stays put.
- `lib/config/site.ts` — brand strings and navigation config. Nav lives here, not inline in components, so desktop and mobile nav can't drift.
- `lib/utils.ts` — `cn()` class merger (clsx + tailwind-merge).
- `hooks/` — shared React hooks.

Components are named for their surface (`site-header`, `dashboard-sidebar`), and the file name matches the exported component.

Import via the `@/*` alias (`@/components/ui/button`, `@/lib/utils`), never relative paths that climb out of a directory.

### Route groups

`SiteHeader` currently mounts in the root layout, which is fine while the
marketing site is the only surface. Once the dashboard or auth screens land,
split into route groups — `app/(marketing)/layout.tsx`, `app/(auth)/`,
`app/(dashboard)/` — and move the header into the marketing group's layout so
the app shell isn't inheriting marketing chrome.

## Design references

The measured baseline: 1152px content box (`max-w-[1200px] px-6`), 70px header,
40px controls. Radii derive from `--radius` (10px): `rounded-lg` for
controls, `rounded-xl` for cards. The designs were authored a step rounder;
the scale was pulled in on purpose, so don't "correct" it back.

The hero backdrop is three layers: the 58px `.bg-hero-grid`, three blurred
`.orb`s, and a fade to `--background`. Orb opacity comes from
`--orb-strong` / `--orb-soft` / `--ambient`, which were re-fitted against the
alpha profile of the dark export — the shipped values were about 1.9x too
strong. Re-measure against `ui-design/` before touching them.

## Conventions

- Components are Server Components by default; add `"use client"` only when a component needs state, effects, or browser APIs.
- Style with Tailwind utility classes composed through `cn()`. Use the CSS variable tokens defined in `app/globals.css` (`bg-background`, `text-muted-foreground`, …) instead of raw color values, so light/dark both work.
- Variants come from `class-variance-authority`; icons from `lucide-react`.
- Theming is `next-themes` with `attribute="class"`; pressing `d` toggles dark mode (see `components/theme-provider.tsx`).
- Prettier config is authoritative: no semicolons, double quotes, 2-space indent, 80 columns, `prettier-plugin-tailwindcss` sorts class names. Run `npm run format` after editing.

## shadcn/ui

`components.json` pins style `base-nova`, base color `neutral`, RSC on, CSS variables on, lucide icons. Components are built on `@base-ui/react`. Don't change these settings casually — they determine what the CLI generates.
